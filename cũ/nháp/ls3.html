import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.netflix.eureka.server.EnableEurekaServer;

@SpringBootApplication
@EnableEurekaServer
public class EurekaServerApplication {

    public static void main(String[] args) {
        SpringApplication.run(
                EurekaServerApplication.class, args);
    }
}

04Giao tiếp giữa các Microservice bằng Eureka

Đây là phần rất quan trọng trong kiến trúc Microservices: gọi dịch vụ thông qua tên định danh thay vì địa chỉ IP và port cố định.

4.1. Vấn đề khi gọi API bằng địa chỉ cố định

Giả sử Product Service cần lấy thông tin người dùng từ User Service. Cách thông thường là gọi trực tiếp:

Gọi trực tiếp (không khuyến nghị)
http://localhost:8082/api/users

Tuy nhiên, cách này có một số hạn chế:

  • Nếu User Service đổi port thì phải sửa code.
  • Nếu User Service chạy trên một máy chủ khác thì địa chỉ sẽ thay đổi.
  • Nếu có nhiều instance của User Service thì khó lựa chọn instance để gọi.

Trong Microservices, chúng ta muốn gọi dịch vụ thông qua tên định danh thay vì phải nhớ địa chỉ IP và port:

Gọi qua tên dịch vụ
http://USER-SERVICE/api/users

Eureka sẽ giúp ứng dụng tìm ra địa chỉ thực tế của USER-SERVICE.

4.2. Thêm dependency LoadBalancer

Mở project product-service, thêm vào pom.xml:

pom.xml — product-service
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>

Dependency này hỗ trợ lựa chọn instance của một dịch vụ khi có nhiều instance cùng đăng ký.

4.3. Tạo cấu hình RestClient

Tạo package com.example.productservice.config và class RestClientConfig.java:

RestClientConfig.java
package com.example.productservice.config;

import org.springframework.cloud.client.loadbalancer.LoadBalanced;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Primary;
import org.springframework.web.client.RestClient;

@Configuration
public class RestClientConfig {

    @Bean
    @LoadBalanced
    public RestClient.Builder loadBalancedRestClientBuilder() {
        return RestClient.builder();
    }

    @Bean
    @Primary
    public RestClient.Builder restClientBuilder() {
        return RestClient.builder();
    }
}
Thành phầnÝ nghĩa
@ConfigurationĐánh dấu class cấu hình Spring
@BeanĐăng ký đối tượng vào Spring Container
RestClient.BuilderĐối tượng xây dựng HTTP Client
@LoadBalancedCho phép gọi dịch vụ thông qua tên Service và lựa chọn instance

4.4. Tạo client gọi User Service

Trong Product Service, tạo class UserClient.java:

UserClient.java
package com.example.productservice.client;

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

@Component
public class UserClient {

    private final RestClient restClient;

    public UserClient(
            @Qualifier("loadBalancedRestClientBuilder") RestClient.Builder builder) {
        this.restClient = builder.build();
    }

    public String getUsers() {
        return restClient.get()
                .uri("http://user-service/api/users")
                .retrieve()
                .body(String.class);
    }
}
Điểm quan trọng: .uri("http://user-service/api/users") — ở đây user-service chính là tên được khai báo trong spring.application.name=user-service. Chúng ta không cần ghi localhost:8082.

4.5. Tạo API kiểm tra giao tiếp

Cập nhật ProductController.java:

ProductController.java
package com.example.productservice.controller;

import com.example.productservice.client.UserClient;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {

    private final UserClient userClient;

    @GetMapping
    public String getProducts() {
        return "Danh sách sản phẩm từ Product Service";
    }

    @GetMapping("/users")
    public String getUsersFromUserService() {
        return userClient.getUsers();
    }
}

05API Gateway với Spring Cloud Gateway

Xây dựng cổng giao tiếp trung tâm để Client không cần gọi trực tiếp từng Microservice, mà chỉ cần gửi request đến một địa chỉ duy nhất.

5.1. Vì sao cần API Gateway?

Hiện tại Client vẫn phải gọi trực tiếp từng Microservice:

Frontend
   │
   ├────► Product Service :8081
   │
   └────► User Service    :8082

Điều này chưa thực sự thuận tiện khi hệ thống có nhiều Microservice.

API Gateway giải quyết vấn đề này bằng cách tạo ra một cổng giao tiếp trung tâm. Client chỉ cần gửi request đến Gateway, Gateway sẽ tự động chuyển request đến Microservice phù hợp.

API Gateway là gì?

API Gateway là một thành phần đứng giữa Client và các Microservice. Nó tiếp nhận request từ Client, xác định request cần chuyển đến dịch vụ nào, sau đó chuyển tiếp request và trả response về Client.

Đường dẫnChuyển đến
/api/products/**Product Service
/api/users/**User Service

spring.cloud.gateway.server.webflux.discovery.locator.lower-case-service-id=true

Hai cấu hình cuối cho phép Gateway tự động tạo route dựa trên danh sách dịch vụ mà Eureka cung cấp.

5.5. Cơ chế tự động định tuyến

Khi bật Discovery Locator, Gateway có thể tự động tạo route cho các Microservice đã đăng ký với Eureka:

ServiceĐịa chỉ gọi qua Gateway
Product Servicehttp://localhost:8080/product-service/api/products
User Servicehttp://localhost:8080/user-service/api/users

Gateway nhận request, loại bỏ phần tiền tố tên Service rồi chuyển tiếp đến đúng Microservice.

5.6. Khởi chạy và kiểm tra API Gateway

Khởi chạy theo thứ tự:

  1. eureka-server
  2. product-service
  3. user-service
  4. api-gateway

Truy cập http://localhost:8761 — bạn sẽ thấy thêm API-GATEWAY trong danh sách dịch vụ đã đăng ký.

Bây giờ, thay vì gọi trực tiếp Product Service, hãy gọi qua Gateway:

Kiểm tra qua Gateway
# Product Service
GET http://localhost:8080/product-service/api/products

# User Service
GET http://localhost:8080/user-service/api/users

# Product Service gọi User Service
GET http://localhost:8080/product-service/api/products/users
RequestDịch vụ xử lý
/product-service/api/productsProduct Service
/user-service/api/usersUser Service
/product-service/api/products/usersProduct Service, sau đó gọi User Service

Nếu các API trả về đúng kết quả thì Gateway đã định tuyến thành công.

Với Discovery Locator, Gateway mặc định tạo đường dẫn theo dạng /{serviceId}/**, chuyển tiếp đến dịch vụ qua lb://serviceId và loại bỏ tiền tố tên dịch vụ trước khi gửi request.

5.7. Cấu hình Route thủ công

Ngoài cách tự động tạo route từ Eureka, chúng ta có thể tự định nghĩa từng route. Cách này giúp kiểm soát rõ ràng URL bên ngoài và Microservice đích.

Ví dụ, thay vì gọi http://localhost:8080/product-service/api/products, chúng ta muốn gọi http://localhost:8080/api/products và Gateway tự chuyển đến Product Service.

application.properties — route thủ công
# Tắt tự động tạo route
spring.cloud.gateway.server.webflux.discovery.locator.enabled=false

# Route đến Product Service
spring.cloud.gateway.server.webflux.routes[0].id=product-service
spring.cloud.gateway.server.webflux.routes[0].uri=lb://product-service
spring.cloud.gateway.server.webflux.routes[0].predicates[0]=Path=/api/products/**

# Route đến User Service
spring.cloud.gateway.server.webflux.routes[1].id=user-service
spring.cloud.gateway.server.webflux.routes[1].uri=lb://user-service
spring.cloud.gateway.server.webflux.routes[1].predicates[0]=Path=/api/users/**
Cấu hìnhÝ nghĩa
routes[0].idĐịnh danh route
routes[0].uriMicroservice đích
predicatesĐiều kiện để route được chọn
PathKiểm tra đường dẫn request
lb://Tìm dịch vụ và lựa chọn instance thông qua LoadBalancer
Lưu ý: lb://product-service không phải địa chỉ URL thông thường. Đây là cách chỉ định dịch vụ đích thông qua cơ chế Service Discovery và LoadBalancer.

5.9. Tìm hiểu Route, Predicate và Filter

Đây là ba khái niệm quan trọng nhất khi làm việc với Spring Cloud Gateway.

1. Route

Route là cấu hình định tuyến, xác định request sẽ được chuyển đến Microservice nào.

Route
spring.cloud.gateway.server.webflux.routes[0].id=product-service
spring.cloud.gateway.server.webflux.routes[0].uri=lb://product-service

2. Predicate

Predicate là điều kiện để Gateway xác định một request có phù hợp với Route hay không.

Predicate
spring.cloud.gateway.server.webflux.routes[0].predicates[0]=Path=/api/products/**

Nghĩa là Route này chỉ nhận những request có đường dẫn bắt đầu bằng /api/products/ hoặc khớp với /api/products.

3. Filter

Filter cho phép can thiệp vào request trước khi chuyển đến Microservice hoặc response trước khi trả về Client.

Thêm header vào request
spring.cloud.gateway.server.webflux.routes[0].filters[0]=AddRequestHeader=X-Gateway,MyGateway

Khi request được chuyển đến Product Service, nó sẽ có thêm header: X-Gateway: MyGateway

Nhờ Filter, chúng ta có thể triển khai nhiều chức năng như:

  • Xác thực JWT tại Gateway.
  • Ghi log request.
  • Giới hạn số lượng request (Rate Limiting).
  • Thay đổi đường dẫn (Rewrite Path).
  • Thêm hoặc xóa HTTP Header.
