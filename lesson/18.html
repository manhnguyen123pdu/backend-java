TỔNG QUAN VỀ LẬP TRÌNH WEB

I. MỤC TIÊU BÀI HỌC

Trong quá trình học lập trình, học viên thường bắt đầu bằng việc viết chương trình, xây dựng giao diện hoặc làm việc với cơ sở dữ liệu. Tuy nhiên, để phát triển một ứng dụng Web hoàn chỉnh, cần hiểu cách những thành phần này kết hợp với nhau thành một hệ thống thống nhất.

Bài học này cung cấp bức tranh tổng thể về lập trình Web, làm nền tảng cho các nội dung tiếp theo trong khóa Backend Java Spring Boot.

Sau bài học, học viên cần đạt được các mục tiêu sau:

Về kiến thức

  • Hiểu bản chất của lập trình Web, quá trình phát triển của ứng dụng Web và vai trò của Web trong các hệ thống phần mềm hiện đại.
  • Phân biệt được Website thiên về cung cấp thông tin, Web Application có nhiều chức năng tương tác và Backend API cung cấp dữ liệu, chức năng cho các ứng dụng khác.
  • Hiểu mô hình Client – Server và cách các thành phần trong ứng dụng Web giao tiếp với nhau.
  • Phân biệt vai trò của Frontend, Backend và Database.
  • Hiểu được tại sao một ứng dụng cần xử lý nghiệp vụ phía máy chủ thay vì chỉ xây dựng giao diện.
  • Nhận biết vai trò của Java, Spring Framework, Spring Boot, MySQL và các công cụ phát triển phần mềm.
  • Hiểu sự khác biệt cơ bản giữa môi trường phát triển trên máy cá nhân và môi trường triển khai thực tế.

Về tư duy lập trình

  • Biết phân tích một chức năng Web thành các thành phần có trách nhiệm riêng.
  • Biết mô tả luồng dữ liệu từ người dùng đến hệ thống xử lý và quay trở lại giao diện.
  • Bước đầu hình thành tư duy phát triển ứng dụng theo yêu cầu nghiệp vụ, thay vì chỉ tập trung viết mã nguồn.

Về định hướng học tập

  • Hiểu vị trí của Backend trong quy trình phát triển phần mềm.
  • Nắm được mục đích của việc học Java Spring Boot.
  • Hình dung được lộ trình từ kiến thức nền tảng đến xây dựng, kiểm thử và triển khai một ứng dụng thực tế.

II. TỔNG QUAN VỀ LẬP TRÌNH WEB

2.1. Khái niệm lập trình Web

2.1.1. Lập trình Web là gì?

Lập trình Web là quá trình phân tích, thiết kế, xây dựng, kiểm thử và duy trì các website hoặc ứng dụng có thể được truy cập thông qua mạng, thường bằng trình duyệt Web hoặc thông qua những ứng dụng có khả năng giao tiếp với máy chủ.

Một ứng dụng Web không đơn thuần là một trang có văn bản, hình ảnh và nút bấm. Đối với những hệ thống có nghiệp vụ, ứng dụng còn cần tiếp nhận thông tin, xử lý yêu cầu, quản lý dữ liệu, kiểm soát quyền truy cập và trả về kết quả phù hợp.

Ví dụ, một hệ thống quản lý sinh viên có thể cung cấp các chức năng:

  • Xem danh sách sinh viên.
  • Tìm kiếm sinh viên theo mã hoặc họ tên.
  • Thêm mới hồ sơ sinh viên.
  • Cập nhật thông tin cá nhân.
  • Quản lý lớp học.
  • Theo dõi điểm số và kết quả học tập.
  • Quản lý tài khoản giảng viên và nhân viên.

Để xây dựng hệ thống này, lập trình viên cần giải quyết nhiều vấn đề khác nhau. Giao diện phải hiển thị thông tin rõ ràng; chương trình phải xử lý đúng nghiệp vụ; dữ liệu phải được lưu trữ; đồng thời, người dùng chỉ được thực hiện những thao tác phù hợp với quyền hạn của mình.

Như vậy, lập trình Web là xây dựng một hệ thống phần mềm có khả năng cung cấp chức năng thông qua môi trường Web, chứ không chỉ là thiết kế giao diện trên trình duyệt.

2.1.2. Một ứng dụng Web khác gì với một chương trình thông thường?

Hãy so sánh hai tình huống.

Tình huống 1: Chương trình quản lý sinh viên chạy trên một máy tính

Lập trình viên xây dựng một chương trình Java có giao diện Swing. Chương trình được cài đặt và chạy trên máy tính của nhân viên quản lý. Nếu dữ liệu được lưu trong một tệp cục bộ hoặc cơ sở dữ liệu trên máy đó, việc sử dụng hệ thống sẽ phụ thuộc vào cách chương trình và dữ liệu được triển khai.

Tình huống 2: Hệ thống quản lý sinh viên chạy trên Web

Nhà trường triển khai ứng dụng trên máy chủ. Giảng viên có thể mở trình duyệt để xem danh sách lớp, trong khi nhân viên quản lý sử dụng cùng hệ thống để cập nhật hồ sơ sinh viên. Các thao tác được xử lý thông qua hệ thống chung và dữ liệu có thể được quản lý tập trung.

Bảng trên mô tả những đặc điểm phổ biến, không phải quy tắc tuyệt đối. Chương trình cục bộ vẫn có thể kết nối máy chủ; ứng dụng Web cũng có thể hoạt động trong mạng nội bộ thay vì Internet công cộng.

Điểm khác biệt quan trọng nằm ở cách phần mềm được phân phối, cách người dùng tương tác và cách các thành phần trong hệ thống được tổ chức.

2.2. Sự phát triển của ứng dụng Web

Để hiểu tại sao ứng dụng Web ngày nay thường có cả Frontend, Backend và Database, cần nhìn qua quá trình phát triển của Web.

2.2.1. Website tĩnh

Ở giai đoạn đầu, nhiều website chủ yếu cung cấp nội dung có sẵn như văn bản, hình ảnh và thông tin giới thiệu.

Ví dụ, một website giới thiệu trung tâm đào tạo có thể hiển thị địa chỉ, thông tin giảng viên, chương trình học và lịch khai giảng.

Đặc điểm của website tĩnh là nội dung thường được chuẩn bị trước. Khi người dùng truy cập, hệ thống cung cấp nội dung tương ứng mà không nhất thiết phải xử lý nghiệp vụ riêng cho từng người dùng.

Website tĩnh phù hợp với những nhu cầu cung cấp thông tin đơn giản. Tuy nhiên, nếu muốn xây dựng chức năng đăng nhập, quản lý học viên hoặc cập nhật dữ liệu thường xuyên, hệ thống cần thêm các cơ chế xử lý phù hợp.

2.2.2. Website động và ứng dụng Web

Khi nhu cầu sử dụng Web tăng lên, các hệ thống bắt đầu hỗ trợ nội dung thay đổi theo dữ liệu, tài khoản và hành động của người dùng.

Ví dụ, một website bán hàng có thể hiển thị sản phẩm hiện có trong kho, đơn hàng của từng khách hàng và thông tin tài khoản sau khi đăng nhập.

Hai người dùng truy cập cùng một ứng dụng có thể nhận được những thông tin khác nhau, tùy theo dữ liệu và quyền truy cập của họ.

Để đáp ứng nhu cầu đó, ứng dụng cần có khả năng xử lý yêu cầu và làm việc với dữ liệu. Đây là một trong những lý do Backend trở thành thành phần quan trọng trong phát triển Web.

2.2.3. Ứng dụng Web hiện đại

Ngày nay, ứng dụng Web có thể được tổ chức thành nhiều thành phần chuyên biệt.

Giao diện có thể được phát triển bằng React hoặc các công nghệ Frontend khác. Backend có thể sử dụng Java Spring Boot để xử lý nghiệp vụ. Dữ liệu được lưu trong MySQL hoặc một hệ quản trị cơ sở dữ liệu phù hợp. Các thành phần có thể được triển khai trên những máy chủ hoặc dịch vụ khác nhau.

Ví dụ:

Người dùng
    |
    v
Giao diện Web
    |
    v
Backend Java Spring Boot
    |
    v
Cơ sở dữ liệu MySQL

Đây là mô hình khái quát. Trong hệ thống lớn, kiến trúc có thể bao gồm nhiều Backend, bộ nhớ đệm, dịch vụ lưu trữ tệp và các thành phần trung gian khác.

Trong phạm vi khóa học, chúng ta bắt đầu từ mô hình đơn giản để hiểu rõ trách nhiệm của từng thành phần trước khi tìm hiểu các kiến trúc phức tạp hơn.

2.3. Website, Web Application và Web API

Ba khái niệm này có liên quan với nhau nhưng không hoàn toàn giống nhau.

2.3.1. Website

Website thường được sử dụng để cung cấp thông tin cho người truy cập.

Ví dụ:

  • Website giới thiệu doanh nghiệp.
  • Website giới thiệu khóa học.
  • Website tin tức.
  • Website cung cấp thông tin sản phẩm.

Một website vẫn có thể chứa các chức năng tương tác, nhưng mục đích nổi bật thường là trình bày và cung cấp thông tin.

2.3.2. Web Application

Web Application là ứng dụng Web cho phép người dùng thực hiện các công việc thông qua giao diện.

Ví dụ:

  • Hệ thống quản lý sinh viên.
  • Hệ thống quản lý bán hàng.
  • Ứng dụng quản lý kho.
  • Hệ thống đặt lịch khám.
  • Nền tảng học trực tuyến.

Điểm nổi bật của Web Application là người dùng không chỉ đọc thông tin mà còn thực hiện các thao tác nghiệp vụ.

2.3.3. Web API

Web API là giao diện giao tiếp cho phép một chương trình gửi yêu cầu đến một hệ thống khác để sử dụng dữ liệu hoặc chức năng mà hệ thống đó cung cấp.

Ví dụ, một ứng dụng Frontend cần lấy danh sách sản phẩm. Thay vì tự truy cập cơ sở dữ liệu, ứng dụng gửi yêu cầu đến Backend API. Backend xử lý yêu cầu và trả dữ liệu để Frontend sử dụng.

Web API cũng có thể phục vụ ứng dụng điện thoại hoặc những hệ thống khác, không chỉ riêng giao diện chạy trên trình duyệt.

Có thể hình dung:

                 +-------------------+
                 |   Backend API     |
                 +---------+---------+
                           |
              +------------+------------+
              |            |            |
              v            v            v
          Website     Ứng dụng      Hệ thống
          trên Web    điện thoại    bên ngoài

Trong khóa học Java Spring Boot, học viên sẽ từng bước xây dựng Backend có khả năng cung cấp API cho các ứng dụng khác sử dụng.

Ở bài đầu tiên, chỉ cần hiểu mục đích của API là tạo ra một cách giao tiếp có tổ chức giữa các thành phần. Cách thiết kế và triển khai API sẽ được học ở những bài tiếp theo.

2.4. Vì sao cần học lập trình Web?

Lập trình Web không chỉ phục vụ việc xây dựng các trang thông tin mà còn là nền tảng để phát triển những hệ thống phục vụ công việc thực tế.

2.4.1. Giải quyết bài toán nghiệp vụ

Một doanh nghiệp có thể quản lý sản phẩm bằng bảng tính ở giai đoạn đầu. Khi số lượng sản phẩm, nhân viên và đơn hàng tăng lên, việc quản lý thủ công dễ dẫn đến sai sót, trùng lặp hoặc khó kiểm soát.

Ứng dụng Web có thể tập trung dữ liệu, chuẩn hóa quy trình và cung cấp chức năng phù hợp với từng nhóm người dùng.

2.4.2. Hỗ trợ nhiều người dùng

Khi hệ thống được triển khai phù hợp, nhiều người dùng có thể truy cập cùng một ứng dụng từ các thiết bị khác nhau.

Ví dụ, nhân viên kho cập nhật số lượng sản phẩm, nhân viên bán hàng tạo đơn hàng và người quản lý theo dõi báo cáo. Các thao tác có thể phối hợp thông qua hệ thống chung.

2.4.3. Dễ phát triển thêm chức năng

Một hệ thống được thiết kế tốt có thể được mở rộng khi nhu cầu thay đổi.

Ví dụ, ứng dụng quản lý sinh viên ban đầu chỉ có chức năng quản lý hồ sơ. Sau đó, hệ thống có thể bổ sung quản lý lớp học, điểm số, tài khoản và báo cáo.

Việc mở rộng thuận lợi hay không phụ thuộc nhiều vào cách phân tích yêu cầu và tổ chức kiến trúc ngay từ đầu.

2.4.4. Tạo nền tảng cho các công nghệ khác

Kiến thức Web còn liên quan đến bảo mật, triển khai phần mềm, hệ thống phân tán, quản lý dữ liệu và tích hợp dịch vụ.

Vì vậy, học lập trình Web không chỉ giúp học viên tạo ra một ứng dụng mà còn hình thành nền tảng để tiếp cận những lĩnh vực kỹ thuật rộng hơn.

III. KIẾN TRÚC TỔNG QUAN CỦA MỘT ỨNG DỤNG WEB

3.1. Khái niệm kiến trúc ứng dụng

Kiến trúc ứng dụng là cách tổ chức các thành phần của phần mềm và xác định trách nhiệm, mối quan hệ giữa chúng.

Khi xây dựng một ứng dụng nhỏ, lập trình viên có thể viết nhiều chức năng trong cùng một chương trình. Tuy nhiên, khi hệ thống phát triển, việc đặt toàn bộ logic, giao diện và thao tác dữ liệu vào một nơi sẽ khiến chương trình khó đọc, khó kiểm thử và khó bảo trì.

Do đó, ứng dụng thường được tổ chức thành những thành phần có trách nhiệm riêng.

Đối với ứng dụng Web cơ bản, có thể bắt đầu bằng mô hình ba thành phần:

  1. Frontend: giao diện và tương tác với người dùng.
  2. Backend: xử lý yêu cầu và nghiệp vụ.
  3. Database: lưu trữ và quản lý dữ liệu.
+--------------------------------+
|            FRONTEND            |
| Giao diện và tương tác          |
+---------------+----------------+
                |
                | Giao tiếp với Backend
                v
+--------------------------------+
|             BACKEND            |
| Xử lý yêu cầu và nghiệp vụ      |
+---------------+----------------+
                |
                | Truy cập dữ liệu
                v
+--------------------------------+
|            DATABASE            |
| Lưu trữ và quản lý dữ liệu      |
+--------------------------------+

Cần phân biệt rằng đây là mô hình phân chia trách nhiệm, không nhất thiết là ba máy tính riêng biệt. Trong một hệ thống nhỏ, Backend và Database có thể chạy trên cùng một máy chủ. Frontend cũng có thể được phục vụ từ cùng môi trường triển khai.

Điều quan trọng là hiểu rõ mỗi thành phần làm nhiệm vụ gì và vì sao không nên tùy tiện trộn lẫn mọi trách nhiệm.

3.2. Frontend – Thành phần giao tiếp với người dùng

Frontend là phần giao diện mà người dùng trực tiếp nhìn thấy và thao tác.

Frontend thường đảm nhiệm:

  • Trình bày thông tin theo bố cục dễ hiểu.
  • Thu thập dữ liệu người dùng nhập vào.
  • Hiển thị danh sách, biểu mẫu và thông báo.
  • Cho phép người dùng thực hiện các thao tác trên giao diện.
  • Gửi yêu cầu đến Backend và hiển thị kết quả nhận được.

Các công nghệ nền tảng thường gặp là HTML, CSS và JavaScript.

HTML tổ chức nội dung; CSS định dạng cách hiển thị; JavaScript hỗ trợ xử lý tương tác trong trình duyệt. Những thư viện hoặc Framework như React, Vue và Angular giúp xây dựng giao diện phức tạp có cấu trúc hơn.

Ví dụ, trang quản lý sinh viên có một bảng chứa mã sinh viên, họ tên và lớp học. Frontend chịu trách nhiệm hiển thị bảng, cung cấp nút thêm mới và trình bày kết quả sau khi dữ liệu được tải về.

Tuy nhiên, việc hiển thị một nút “Xóa” không đồng nghĩa người dùng chắc chắn có quyền xóa dữ liệu. Giao diện có thể hỗ trợ trải nghiệm người dùng, nhưng Backend vẫn phải kiểm tra quyền thực hiện thao tác.

Đây là điểm phân biệt quan trọng giữa phần trình bày và phần xử lý có thẩm quyền đối với dữ liệu.

3.3. Backend – Thành phần xử lý nghiệp vụ

Backend là phần chương trình chạy phía máy chủ, có nhiệm vụ tiếp nhận yêu cầu, thực hiện xử lý và trả kết quả.

Backend có thể đảm nhiệm các trách nhiệm sau:

Tiếp nhận yêu cầu: Nhận thông tin từ Frontend hoặc một ứng dụng khác.

Xử lý nghiệp vụ: Thực hiện các quy tắc của hệ thống, chẳng hạn xác định một đơn hàng có đủ điều kiện được tạo hay không.

Kiểm tra dữ liệu: Đảm bảo dữ liệu đầu vào đáp ứng các điều kiện cần thiết.

Phối hợp với Database: Đọc, tạo mới, cập nhật hoặc xóa dữ liệu theo nghiệp vụ được phép.

Kiểm soát truy cập: Xác minh người dùng và kiểm tra quyền khi thực hiện các thao tác cần bảo vệ.

Trả kết quả: Cung cấp dữ liệu hoặc thông báo để phía gửi yêu cầu biết kết quả xử lý.

Ví dụ, trong hệ thống bán hàng, người dùng nhấn nút tạo đơn hàng. Backend không nên chỉ nhận dữ liệu rồi lưu ngay một cách máy móc. Hệ thống còn cần kiểm tra thông tin sản phẩm, số lượng và các điều kiện nghiệp vụ liên quan.

Tùy theo yêu cầu, Backend có thể phải phối hợp nhiều thành phần trước khi quyết định kết quả cuối cùng.

Vì sao không để toàn bộ nghiệp vụ ở Frontend?

Giả sử giao diện có chức năng giảm giá sản phẩm. Nếu giá trị giảm giá chỉ được kiểm tra ở giao diện, người dùng có thể sửa dữ liệu gửi đi hoặc bỏ qua các bước kiểm tra trên giao diện.

Do đó, những quy tắc nghiệp vụ quan trọng phải được thực thi tại nơi có thể kiểm soát việc xử lý, thường là Backend.

Frontend có thể hỗ trợ kiểm tra dữ liệu để người dùng dễ thao tác hơn, nhưng không nên được xem là ranh giới bảo mật duy nhất.

Nguyên tắc cần nhớ: Frontend giúp người dùng tương tác với hệ thống; Backend chịu trách nhiệm xử lý nghiệp vụ và kiểm soát những thao tác thuộc phạm vi của hệ thống.

3.4. Database – Thành phần lưu trữ dữ liệu

Database được sử dụng để lưu trữ thông tin một cách có tổ chức, giúp ứng dụng có thể truy xuất và cập nhật dữ liệu khi cần.

Hãy xét hệ thống quản lý sinh viên.

Nếu chương trình chỉ giữ thông tin sinh viên trong bộ nhớ khi đang chạy, dữ liệu đó có thể mất khi ứng dụng kết thúc. Để quản lý hồ sơ lâu dài, hệ thống cần cơ chế lưu trữ phù hợp.

Với MySQL, dữ liệu thường được tổ chức trong các bảng có cấu trúc xác định.

Ví dụ, hệ thống có thể có bảng sinh viên và bảng lớp học. Thông tin sinh viên được lưu trong bảng sinh viên, còn thông tin lớp học được quản lý trong bảng lớp học. Các mối quan hệ giữa dữ liệu có thể được thiết kế để hạn chế trùng lặp và duy trì tính nhất quán.

Ở giai đoạn tổng quan, học viên cần hiểu ba vấn đề:

  • Dữ liệu phải được tổ chức phù hợp với nghiệp vụ.
  • Ứng dụng cần có cơ chế truy cập và cập nhật dữ liệu.
  • Việc truy cập dữ liệu phải được kiểm soát, tránh làm hỏng hoặc để lộ thông tin.

Trong khóa học, MySQL sẽ là hệ quản trị cơ sở dữ liệu chính để học viên thực hành cùng Java Spring Boot.

3.5. Mối quan hệ giữa ba thành phần qua một ví dụ

Giả sử người dùng muốn thêm một sinh viên mới vào hệ thống.

Quá trình có thể được phân tích như sau:

Giai đoạn 1 – Tương tác: Người dùng mở biểu mẫu và nhập mã sinh viên, họ tên, lớp học. Đây là phần Frontend.

Giai đoạn 2 – Gửi yêu cầu: Sau khi người dùng xác nhận, Frontend gửi dữ liệu đến Backend.

Giai đoạn 3 – Xử lý nghiệp vụ: Backend kiểm tra thông tin theo những quy tắc của hệ thống, chẳng hạn các trường bắt buộc phải có dữ liệu.

Giai đoạn 4 – Lưu trữ: Nếu yêu cầu hợp lệ, Backend thực hiện thao tác lưu thông tin vào Database theo thiết kế của ứng dụng.

Giai đoạn 5 – Trả kết quả: Backend trả kết quả xử lý cho Frontend.

Giai đoạn 6 – Hiển thị: Frontend thông báo kết quả hoặc cập nhật danh sách sinh viên để người dùng quan sát.

Ví dụ này cho thấy một chức năng nhìn đơn giản trên giao diện thực tế có thể liên quan đến nhiều thành phần. Vì vậy, khi phát triển Backend, lập trình viên cần hiểu toàn bộ luồng xử lý thay vì chỉ quan tâm đến một đoạn mã riêng lẻ.

3.7. Những nguyên tắc kiến trúc cần hiểu từ đầu

Ở bài tổng quan, học viên chưa cần học cách triển khai kiến trúc nhiều tầng. Tuy nhiên, nên hình thành một số nguyên tắc tư duy cơ bản.

Thứ nhất, mỗi thành phần cần có trách nhiệm rõ ràng. Giao diện không nên tự đảm nhiệm mọi nghiệp vụ; Database cũng không thay thế toàn bộ logic ứng dụng.

Thứ hai, các thành phần phải phối hợp theo một cách xác định. Frontend cần biết nơi gửi yêu cầu; Backend cần biết cách xử lý và lấy dữ liệu; Database cần có cấu trúc phù hợp.

Thứ ba, dữ liệu phải được kiểm soát. Không nên cho phép mọi người dùng tự do truy cập toàn bộ dữ liệu hoặc thực hiện mọi thao tác.

Thứ tư, thiết kế cần hướng đến khả năng bảo trì. Một ứng dụng không chỉ cần chạy được ở hiện tại mà còn cần đủ rõ ràng để có thể sửa đổi và mở rộng trong tương lai.

Những nguyên tắc này sẽ tiếp tục xuất hiện trong quá trình học Java, Spring Boot, cơ sở dữ liệu và bảo mật.

IV. MÔ HÌNH CLIENT – SERVER VÀ LUỒNG HOẠT ĐỘNG CỦA WEB

4.1. Client là gì?

Client là thành phần gửi yêu cầu để sử dụng dịch vụ do một thành phần khác cung cấp.

Trong ứng dụng Web, Client có thể là:

  • Trình duyệt Google Chrome hoặc Microsoft Edge.
  • Giao diện Frontend được xây dựng bằng React.
  • Ứng dụng điện thoại.
  • Công cụ Postman dùng để kiểm thử.
  • Một chương trình khác cần sử dụng chức năng của Backend.

Ví dụ, khi mở trang quản lý sản phẩm, trình duyệt đóng vai trò Client. Khi yêu cầu danh sách sản phẩm, Client gửi yêu cầu đến hệ thống cung cấp chức năng tương ứng.

Client không nhất thiết phải là một trình duyệt. Đây là khái niệm rộng hơn, chỉ thành phần sử dụng dịch vụ từ phía cung cấp.

4.2. Server là gì?

Server là thành phần cung cấp dịch vụ, tiếp nhận yêu cầu và trả kết quả cho Client.

Trong ứng dụng Java Spring Boot, chương trình Backend thường chạy trên một máy chủ hoặc môi trường triển khai để nhận yêu cầu từ các Client.

Server có thể xử lý nhiều loại yêu cầu khác nhau, tùy theo chức năng ứng dụng cung cấp.

Ví dụ, Backend của hệ thống quản lý sinh viên có thể cung cấp chức năng lấy danh sách sinh viên, tạo hồ sơ mới hoặc trả về thông tin tài khoản.

Cần phân biệt hai cách dùng từ “Server” trong thực tế:

  • Máy chủ: Máy tính hoặc môi trường hạ tầng nơi chương trình chạy.
  • Chương trình Server: Phần mềm tiếp nhận và xử lý yêu cầu từ Client.

Trong hội thoại kỹ thuật, từ Server đôi khi được dùng cho cả máy chủ lẫn chương trình cung cấp dịch vụ. Học viên cần căn cứ vào ngữ cảnh để hiểu đúng.

4.3. Mô hình Client – Server hoạt động như thế nào?

Mô hình Client – Server tổ chức giao tiếp giữa bên sử dụng dịch vụ và bên cung cấp dịch vụ.

Một luồng hoạt động cơ bản gồm:

  1. Client phát sinh yêu cầu.
  2. Yêu cầu được gửi đến Server.
  3. Server tiếp nhận và xử lý yêu cầu.
  4. Server có thể truy cập Database hoặc phối hợp với các thành phần khác.
  5. Server trả kết quả.
  6. Client sử dụng kết quả để hiển thị hoặc tiếp tục xử lý.
+-------------------+       Yêu cầu       +-------------------+
|                   | ------------------> |                   |
|      CLIENT       |                     |      SERVER       |
|                   | <------------------ |                   |
+-------------------+       Kết quả       +---------+---------+
                                                    |
                                                    v
                                           +-------------------+
                                           |     DATABASE      |
                                           +-------------------+

Sơ đồ trên thể hiện quan hệ tổng quát. Trong một hệ thống thực tế, Server có thể giao tiếp với nhiều dịch vụ khác ngoài Database.

Ví dụ: Xem danh sách sinh viên

Người dùng mở trang danh sách sinh viên. Frontend cần dữ liệu để hiển thị nên gửi yêu cầu đến Backend.

Backend tiếp nhận yêu cầu, lấy dữ liệu phù hợp từ Database rồi trả về. Frontend nhận kết quả và trình bày danh sách trên màn hình.

Ở đây, trình duyệt không nhất thiết phải biết cấu trúc bên trong của Database. Frontend chỉ cần giao tiếp theo cách mà Backend cung cấp.

Điều này giúp hệ thống phân chia trách nhiệm: giao diện tập trung vào trải nghiệm người dùng, còn Backend quản lý nghiệp vụ và quyền truy cập dữ liệu.

4.4. Vì sao cần giao tiếp giữa Client và Server?

Nếu chỉ xây dựng một giao diện tĩnh, trình duyệt có thể hiển thị nội dung được chuẩn bị sẵn. Nhưng khi cần dữ liệu thay đổi theo người dùng hoặc theo trạng thái của hệ thống, ứng dụng phải có cách trao đổi thông tin.

Ví dụ:

  • Người dùng tìm kiếm một sản phẩm.
  • Nhân viên cập nhật số lượng tồn kho.
  • Sinh viên xem điểm của mình.
  • Quản trị viên thêm tài khoản.
  • Ứng dụng điện thoại lấy danh sách đơn hàng.

Trong các trường hợp trên, Client cần gửi thông tin hoặc yêu cầu đến một hệ thống có khả năng xử lý.

Giao tiếp giữa Client và Server là nền tảng giúp ứng dụng Web cung cấp các chức năng động, sử dụng dữ liệu tập trung và hỗ trợ nhiều loại thiết bị.

4.5. Vai trò của giao thức và dữ liệu trao đổi

Khi hai thành phần giao tiếp, chúng cần tuân theo những quy tắc chung để hiểu yêu cầu và kết quả.

Đối với Web, HTTP và HTTPS là những giao thức quan trọng. Chúng quy định cách các bên trao đổi thông tin trong quá trình giao tiếp Web. HTTPS bổ sung cơ chế bảo vệ kết nối bằng TLS.

Ngoài giao thức, hai bên còn cần thống nhất cách biểu diễn dữ liệu. Chẳng hạn, dữ liệu có thể được trao đổi dưới dạng JSON để các chương trình dễ đọc và xử lý.

Ở mức tổng quan, học viên chỉ cần hiểu rằng:

  • Giao thức quy định cách giao tiếp.
  • Dữ liệu trao đổi mang thông tin cần thiết cho quá trình xử lý.
  • Client và Server cần thống nhất cách hiểu yêu cầu và kết quả.

Cách sử dụng HTTP, cấu trúc yêu cầu, các loại dữ liệu và cách xây dựng API sẽ được trình bày ở những bài học riêng.

V. TỔNG QUAN VỀ JAVA VÀ SPRING BOOT

5.1. Java trong phát triển phần mềm

Java là ngôn ngữ lập trình được sử dụng rộng rãi trong phát triển ứng dụng, bao gồm ứng dụng Web, phần mềm doanh nghiệp và các hệ thống xử lý dữ liệu.

Java hỗ trợ lập trình hướng đối tượng, cung cấp hệ sinh thái thư viện phong phú và có nhiều công cụ hỗ trợ xây dựng, kiểm thử, đóng gói ứng dụng.

Trong phát triển Backend, Java được dùng để viết logic xử lý của hệ thống. Lập trình viên sử dụng Java để mô tả dữ liệu, tổ chức các chức năng và xây dựng quy tắc nghiệp vụ.

Ví dụ, trong ứng dụng quản lý sản phẩm, mã nguồn Java có thể thể hiện các quy tắc liên quan đến việc tạo sản phẩm, kiểm tra thông tin và phối hợp với thành phần lưu trữ dữ liệu.

Tuy nhiên, bản thân Java là ngôn ngữ lập trình. Để xây dựng một ứng dụng Web hoàn chỉnh, lập trình viên còn cần các thư viện, Framework và công cụ phù hợp.

5.2. Framework là gì?

Framework là một nền tảng phần mềm cung cấp cấu trúc và các thành phần hỗ trợ để phát triển ứng dụng theo những quy ước nhất định.

Nếu tự xây dựng mọi chức năng từ đầu, lập trình viên phải giải quyết nhiều vấn đề lặp lại, chẳng hạn tổ chức ứng dụng, quản lý các thành phần và xử lý những nhu cầu kỹ thuật phổ biến.

Framework cung cấp những cơ chế có sẵn để giảm bớt công việc đó.

Có thể hình dung:

  • Ngôn ngữ lập trình cung cấp phương tiện để viết chương trình.
  • Framework cung cấp cấu trúc và các cơ chế hỗ trợ xây dựng ứng dụng.
  • Thư viện cung cấp những chức năng mà chương trình có thể sử dụng.

Sự phân biệt này chỉ mang tính khái quát, vì trong thực tế một hệ sinh thái có thể bao gồm nhiều loại thành phần khác nhau.

5.3. Spring Framework là gì?

Spring Framework là một Framework dành cho Java, cung cấp những cơ chế hỗ trợ xây dựng ứng dụng.

Spring có hệ sinh thái rộng, được sử dụng trong các ứng dụng Web, hệ thống doanh nghiệp và nhiều loại phần mềm khác.

Một lợi ích quan trọng của Spring là hỗ trợ tổ chức các thành phần của ứng dụng và quản lý mối quan hệ giữa chúng. Điều này giúp lập trình viên xây dựng chương trình theo cấu trúc rõ ràng hơn.

Spring không chỉ phục vụ việc tạo giao diện Web. Hệ sinh thái Spring còn có những thành phần hỗ trợ truy cập dữ liệu, bảo mật và nhiều nhu cầu phát triển khác.

5.4. Spring Boot là gì?

Spring Boot là công nghệ thuộc hệ sinh thái Spring, được thiết kế để đơn giản hóa quá trình xây dựng, cấu hình và chạy ứng dụng.

Khi phát triển ứng dụng với Spring theo cách truyền thống, lập trình viên có thể phải thực hiện nhiều bước cấu hình. Spring Boot cung cấp những cơ chế mặc định và cấu hình tự động để giảm bớt công việc này trong các trường hợp phổ biến.

Spring Boot còn hỗ trợ đóng gói ứng dụng để chạy với máy chủ nhúng trong cấu hình Web thông dụng. Nhờ đó, quá trình phát triển và chạy ứng dụng có thể đơn giản hơn.

Ví dụ, học viên có thể tạo một dự án Spring Boot, viết các chức năng Backend, chạy ứng dụng trên máy tính và kiểm thử bằng trình duyệt hoặc Postman.

Trong quá trình học, các cấu hình và thành phần cụ thể sẽ được giới thiệu theo từng chủ đề, thay vì yêu cầu học viên ghi nhớ toàn bộ ngay từ bài đầu tiên.

5.6. Vì sao khóa học lựa chọn Java Spring Boot?

Có nhiều công nghệ có thể sử dụng để xây dựng Backend. Việc lựa chọn công nghệ phụ thuộc vào yêu cầu dự án, năng lực đội ngũ và hệ sinh thái mà tổ chức đang sử dụng.

Java Spring Boot phù hợp với định hướng khóa học vì những lý do sau.

Thứ nhất, kế thừa nền tảng Java. Học viên có thể vận dụng kiến thức lập trình hướng đối tượng để xây dựng ứng dụng có cấu trúc.

Thứ hai, hỗ trợ tổ chức mã nguồn. Hệ sinh thái Spring cung cấp những cơ chế giúp các thành phần có trách nhiệm rõ ràng và dễ bảo trì.

Thứ ba, đáp ứng nhu cầu phát triển Backend. Spring Boot hỗ trợ xây dựng ứng dụng Web và API, phù hợp với các hệ thống quản lý và ứng dụng nghiệp vụ.

Thứ tư, có khả năng tích hợp nhiều công nghệ. Ứng dụng có thể làm việc với cơ sở dữ liệu, bộ nhớ đệm, hệ thống bảo mật và các dịch vụ khác.

Thứ năm, hỗ trợ triển khai ứng dụng. Ứng dụng có thể được đóng gói và triển khai trên máy chủ hoặc nền tảng Cloud phù hợp.

Tuy nhiên, sử dụng Spring Boot không có nghĩa là bỏ qua kiến thức nền tảng. Muốn làm chủ công nghệ, học viên vẫn cần hiểu Java, tư duy lập trình, cơ sở dữ liệu và nguyên tắc tổ chức phần mềm.

VI. TỪ YÊU CẦU NGHIỆP VỤ ĐẾN ỨNG DỤNG WEB

Một kỹ năng quan trọng của lập trình viên Backend là hiểu bài toán cần giải quyết trước khi bắt đầu viết mã nguồn.

6.1. Yêu cầu nghiệp vụ là gì?

Yêu cầu nghiệp vụ mô tả những điều hệ thống cần thực hiện để đáp ứng nhu cầu của người sử dụng hoặc tổ chức.

Ví dụ, yêu cầu “xây dựng hệ thống quản lý sản phẩm” còn quá chung chung nếu chưa xác định hệ thống cần những chức năng nào.

Khi phân tích sâu hơn, có thể xác định các yêu cầu:

  • Người dùng được xem danh sách sản phẩm.
  • Nhân viên được thêm sản phẩm mới.
  • Nhân viên được cập nhật thông tin sản phẩm.
  • Chỉ người có quyền phù hợp được xóa sản phẩm.
  • Hệ thống cần lưu lại thông tin để có thể sử dụng về sau.

Những yêu cầu này định hướng việc xây dựng giao diện, nghiệp vụ Backend và cách tổ chức dữ liệu.

6.2. Ví dụ phân tích chức năng thêm sản phẩm

Giả sử một cửa hàng muốn bổ sung chức năng thêm sản phẩm vào hệ thống.

Bước 1. Xác định nhu cầu người dùng

Nhân viên cần nhập thông tin sản phẩm để quản lý hàng hóa.

Bước 2. Xác định dữ liệu cần thiết

Thông tin có thể gồm mã sản phẩm, tên sản phẩm, giá bán và số lượng tồn kho.

Bước 3. Xác định trách nhiệm của Frontend

Frontend cung cấp biểu mẫu để nhân viên nhập thông tin và hiển thị kết quả thao tác.

Bước 4. Xác định trách nhiệm của Backend

Backend tiếp nhận dữ liệu, kiểm tra các điều kiện nghiệp vụ và quyết định có thể thực hiện thao tác hay không.

Bước 5. Xác định trách nhiệm của Database

Database lưu thông tin sản phẩm theo cấu trúc dữ liệu đã thiết kế.

Bước 6. Xác định kết quả mong muốn

Nếu thao tác hợp lệ và lưu thành công, hệ thống thông báo kết quả phù hợp. Nếu có lỗi, hệ thống phản hồi để người dùng biết vấn đề cần xử lý.

Bảng phân tích:

Thành phần Trách nhiệm trong chức năng
Người dùngCung cấp thông tin sản phẩm

BackendKiểm tra và xử lý nghiệp vụ
DatabaseLưu thông tin sản phẩm

Qua ví dụ này, học viên có thể thấy rằng một chức năng nghiệp vụ không thuộc riêng một thành phần. Mỗi thành phần đảm nhiệm một phần công việc để hoàn thành mục tiêu chung.

6.3. Tư duy phân tích trước khi lập trình

Trước khi viết mã nguồn cho một chức năng, lập trình viên nên tự đặt ra các câu hỏi:

  1. Ai sẽ sử dụng chức năng này?
  2. Người dùng cần cung cấp thông tin gì?
  3. Hệ thống cần thực hiện những quy tắc nghiệp vụ nào?
  4. Dữ liệu nào cần đọc hoặc lưu trữ?
  5. Những trường hợp nào có thể gây lỗi?
  6. Kết quả cần trả về cho người dùng là gì?

Ở những bài đầu tiên, học viên chưa cần thiết kế toàn bộ hệ thống lớn. Mục tiêu là hình thành thói quen phân tích vấn đề theo từng bước trước khi triển khai.

Đây là nền tảng giúp việc học Spring Boot có ý nghĩa hơn, vì Framework chỉ là công cụ hỗ trợ thực hiện giải pháp chứ không tự quyết định hệ thống cần giải quyết bài toán gì.

Một ứng dụng tốt cần đáp ứng yêu cầu nghiệp vụ, xử lý dữ liệu đúng, có cấu trúc dễ bảo trì, kiểm soát truy cập phù hợp và có khả năng vận hành ổn định.

Đây là những tiêu chí học viên sẽ dần áp dụng khi xây dựng các dự án trong khóa học.

SPRING FRAMEWORK VÀ SPRING BOOT

2.1. Spring Framework là gì?

Spring Framework là một framework mạnh mẽ của Java, giúp lập trình viên xây dựng ứng dụng dễ dàng hơn.

2.2. Spring Boot là gì?

Spring Boot là một dự án con của Spring Framework, được phát triển để đơn giản hóa việc tạo ứng dụng Spring.

Vấn đề trước khi có Spring Boot:

  • Phải cấu hình rất nhiều file XML
  • Phải tự cài đặt và cấu hình server
  • Phải tự quản lý phiên bản thư viện
  • Mất nhiều thời gian cho cấu hình

Spring Boot giải quyết:

  • ✅ Tự động cấu hình - Không cần file XML
  • ✅ Server nhúng - Có sẵn Tomcat, không cần cài đặt
  • ✅ Starter dependencies - Quản lý phiên bản tự động
  • ✅ Cấu hình đơn giản - Chỉ cần file application.properties

  • Tích hợp server sẵn - Có Tomcat, Jetty nhúng, chạy ứng dụng bằng 1 lệnh

CÁC ANNOTATION

annotation (chú thích) là một loại "siêu dữ liệu" (metadata) được đặt trên các lớp, phương thức hoặc trường, dùng để cho framework Spring biết cách xử lý đoạn mã đó. Hiểu một cách đơn giản, nó giống như một "nhãn dán" giúp Spring tự động nhận diện, cấu hình và quản lý mã của bạn mà không cần viết nhiều tệp cấu hình XML phức tạp.

1. @SpringBootApplication

Vị trí: Trên class DemoApplication

Thành phần:

Công thức
@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan

1.1. @Configuration

Đánh dấu class có thể chứa các bean (đối tượng do Spring quản lý). Tương đương với file XML cấu hình ngày xưa.

1.2. @EnableAutoConfiguration

Spring Boot tự động cấu hình dựa trên các dependencies. Ví dụ: có spring-boot-starter-web → tự động cấu hình Tomcat, DispatcherServlet.

1.3. @ComponentScan

Tự động quét các component trong package com.example.demo và các package con. Tìm các annotation: @Controller, @Service, @Repository, @Component.

2. @RestController là gì?

@RestController là annotation dùng trong Spring Boot để tạo REST API.

Nó thực chất là:

Công thức
@RestController = @Controller + @ResponseBody

2.1. @Controller là gì?

Vai trò: Đánh dấu class là Controller trong mô hình MVC.

MVC gồm:

  • Model: xử lý dữ liệu
  • View: giao diện (HTML)
  • Controller: nhận request và trả về view

Thường dùng khi bạn muốn trả về trang HTML.

Ví dụ:

@Controller
@Controller
public class UserController {

    @GetMapping("/home")
    public String home() {
        return "home"; // trả về file home.html
    }
}

Khi truy cập /home, Spring sẽ tìm file home.html và hiển thị giao diện. Mặc định @Controller trả về View.

2.2. @ResponseBody là gì?

Vai trò: Bắt Spring không trả về View, mà trả về dữ liệu trực tiếp.

Ví dụ:

@ResponseBody
@GetMapping("/hello")
@ResponseBody
public String hello() {
    return "Xin chào";
}

Khi gọi /hello, trình duyệt sẽ hiển thị: Xin chào. Không có file HTML nào được render.

Nếu trả về object:

@ResponseBody với Object
@GetMapping("/user")
@ResponseBody
public User getUser() {
    return new User(1, "Manh");
}

Spring sẽ tự động chuyển object thành JSON:

JSON Output
{
  "id": 1,
  "name": "Manh"
}

2.3. @RestController làm gì?

Thay vì viết:

@Controller + @ResponseBody
@Controller
@ResponseBody

Ta chỉ cần viết:

@RestController
@RestController

Ví dụ:

@RestController
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping
    public List<User> getAllUsers() {
        return userService.findAll();
    }
}

Tất cả method trong class này:

  • Đều trả về JSON
  • Không trả về HTML
  • Không cần viết @ResponseBody cho từng method

So sánh nhanh:

Annotation Đặc điểm
@Controller Trả về HTML. Nếu muốn trả về JSON phải thêm @ResponseBody
@ResponseBody Trả về dữ liệu (JSON, text...), không trả về View
@RestController Chuyên dùng để làm REST API, tự động trả về JSON

3. @RequestMapping

3.1. Mục đích

Dùng để ánh xạ (map) URL với class hoặc method trong Controller.

  • Có thể dùng cho tất cả các HTTP method: GET, POST, PUT, DELETE…
  • Có thể đặt ở:
    • Trên class → định nghĩa URL gốc
    • Trên method → định nghĩa URL cụ thể

3.2. Cú pháp

Dùng cơ bản:

Cú pháp
@RequestMapping("/duong-dan")

Dùng đầy đủ:

Cú pháp
@RequestMapping(
    value = "/duong-dan",
    method = RequestMethod.GET
)

3.3. Giải thích cú pháp

  • value: đường dẫn URL.
  • method: loại HTTP method (GET, POST, PUT, DELETE…).
  • RequestMethod.GET: chỉ định request phải là GET.
  • Nếu không ghi method, mặc định chấp nhận tất cả HTTP method.

3.4. Ví dụ ngắn

Ví dụ đặt ở class:

Ví dụ
@RestController
@RequestMapping("/users")
public class UserController {
}

Giải thích: Tất cả API trong class này sẽ bắt đầu bằng /users.

Ví dụ đặt ở method:

Ví dụ
@GetMapping
public String getAll() {
    return "Danh sách user";
}

Nếu viết bằng @RequestMapping:

Ví dụ
@RequestMapping(value = "/users", method = RequestMethod.GET)
public String getAll() {
    return "Danh sách user";
}

4. @GetMapping

4.1. Mục đích

Chuyên dùng để xử lý HTTP GET.

Là phiên bản rút gọn của: @RequestMapping(method = RequestMethod.GET)

Là cách viết hiện đại, gọn hơn, dễ đọc hơn.

4.2. Cú pháp

Cú pháp
@GetMapping("/duong-dan")

Hoặc:

Cú pháp
@GetMapping

4.3. Giải thích cú pháp

  • "/duong-dan": URL của API.
  • Chỉ xử lý request GET.
  • Không cần ghi method = RequestMethod.GET vì đã mặc định.

4.4. Ví dụ ngắn

Ví dụ
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping
    public String getAllUsers() {
        return "Danh sách user";
    }

    @GetMapping("/1")
    public String getUserById() {
        return "User có id = 1";
    }
}

Kết quả:

  • GET /users → gọi getAllUsers()
  • GET /users/1 → gọi getUserById()

So sánh nhanh @RequestMapping và @GetMapping

Annotation Đặc điểm
@RequestMapping Dùng cho mọi HTTP method. Cần chỉ rõ method = RequestMethod.GET nếu muốn giới hạn. Linh hoạt hơn.
@GetMapping Chỉ dùng cho GET. Viết ngắn gọn. Dễ đọc, khuyến khích dùng trong Spring Boot hiện đại.

BÀI TẬP THỰC HÀNH

Bài tập 1: Tạo API chào mừng

Yêu cầu: Tạo API GET / trả về "Welcome to Spring Boot!"

Hướng dẫn:

  1. Trong UserController.java, thêm method mới
  2. Dùng @GetMapping("/")
  3. Return chuỗi "Welcome to Spring Boot!"

Đáp án:

UserController.java
@GetMapping("/")
public String welcome() {
    return "Welcome to Spring Boot!";
}

Kiểm tra: http://localhost:8080/

Bài tập 2: API có tham số

Yêu cầu: Tạo API /user/greet nhận tham số name từ URL, trả về "Hello, {name}!"

Ví dụ: /user/greet?name=Nguyen → "Hello, Nguyen!"

Hướng dẫn:

Dùng @RequestParam để lấy tham số từ URL

Đáp án:

UserController.java
@GetMapping("/greet")
public String greet(@RequestParam String name) {
    return "Hello, " + name + "!";
}

Kiểm tra: http://localhost:8080/user/greet?name=Nguyen

Bài tập 3: Đổi port server

Yêu cầu: Thay đổi port server sang 9090

Hướng dẫn:

  1. Mở file application.properties
  2. Thêm dòng: server.port=9090
  3. Chạy lại ứng dụng

Kiểm tra: http://localhost:9090/user/getAllUser
